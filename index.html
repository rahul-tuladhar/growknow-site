Growknow is a self-checking spec language. Your agent reads a plan that can prove itself wrong: two rules that cannot both hold, a permission that implies an impossible state, a migration that drops a field something still depends on.

The failure this catches

# billing.spec
entity Seat { plan: Plan, status: active | past_due | cancelled }

rule access when seat.status == cancelled   // line 12
  deny all endpoints

invariant past_due_seats_keep_access
  seat.status == past_due implies seat.can_read_data

▲ contradiction: archived export job (line 41) requires
  cancelled seats to authenticate to finish the export.
  line 12 denies authentication, so the export can never
  complete. Two of these three statements must change.

# Prefers: keep the export, scope the deny to user sessions.
✓ 1 contradiction, 2 unresolved assumptions, 0 errors

Spec, then code

Write the plan in a format an agent can check. Annotations are optional per area, the way types are optional in TypeScript. Add rigor where the cost of being wrong is high.

Check, don't read

The checker finds contradictions, unreachable states, and violations of earlier decisions. You get the line numbers and the reasoning, not a document nobody opens.

Runs where you work

Ships as an MCP server and a CLI, so Claude Code, Cursor, and VS Code can call it before writing a line. The spec stays in your repo as grounding context.

Memory that argues back

Decisions from months ago stay in the spec. When a new section contradicts them, the checker says which one, and when it was made.

Who it is for

  1. Staff and senior engineers at startups where shipping outruns review, and a wrong design costs a week.
  2. Teams already using plan mode who have watched a confident plan turn into a broken migration.
  3. Anyone coordinating several agents that need the same source of truth about the system.
